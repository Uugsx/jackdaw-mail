# Проверки качества desktop

## Проверки исправленных сценариев

Из каталога `app`:

```bash
rtk npm run test:regression
rtk npm run build
```

Из каталога `desktop`:

```bash
rtk npm run build
```

Регрессионный набор проверяет перетаскивание и копирование файлов, частичный
перенос, ошибки загрузки и удаления, перенос между аккаунтами, отмену OAuth,
очистку подписок и независимость окон авторизации, а также синхронизацию OWA.
Тест WebDAV поднимает временный локальный сервер; ему нужен доступ к локальному
порту. Настоящие почтовые аккаунты и пользовательские файлы не используются.

Целостность базы писем (чужой текст, вложения, исходник у письма) проверяет
`integrityFuzz.test.ts`; перед выпуском правок базы или синхронизации её
дополнительно проверяют на копии реальной базы — см.
[mail-db-integrity.md](../mail-db-integrity.md).

Эти проверки выполняются в `check-desktop.yml` для pull request и перед
созданием релиза в `publish-desktop-jackdaw.yml`. После их успешного завершения
сохраняется порядок `prepare` → параллельные сборки macOS и Windows.

Lock-файлы в этом репозитории не коммитятся, поэтому CI устанавливает зависимости
через `npm install`. Для `app` и `desktop` требуется `--legacy-peer-deps`: старые
плагины объявляют несовместимые peer-зависимости Svelte/Vite. Для `app` также
используется `--ignore-scripts`: зависимость `svelte-navigator` содержит устаревший
`postinstall`, который пытается вызвать свои не поставляемые в npm dev-зависимости
`is-ci` и `husky`. Версии библиотек в этой проверке не обновляются.

## Общие проверки и оставшийся долг

Из `app`: `rtk npm run check`.

Из `desktop`:

```bash
rtk npm run typecheck
rtk npm run lint:check
rtk npm run format:check
```

Эти команды проверяют весь соответствующий проект без исправления файлов.
Полный typecheck пока завершается с ошибками в старых модулях: несовместимые
типы буферов Web Crypto, устаревшие типы Svelte и библиотек, ошибки моделей
протоколов и условная компиляция. Общие lint и format check также обнаруживают
существующие нарушения. Они пока не являются обязательным условием публикации.

При исправлении этого долга нужно отдельно проверить затронутые протоколы и
затем добавить полные проверки в обязательный CI. Не следует отключать правила,
добавлять массовые подавления ошибок или считать успешную сборку подтверждением
успешного typecheck.
